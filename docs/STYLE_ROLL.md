# Roll 串：实现分析与工坊接入

本页说明 2026-10-15 新增的独立「Roll 串」工作区。产品边界见 [产品宪法](../VIBER_INTENT.md)，当前操作见 [README](../README.md)，长期维护约定见 [产品决策记录](./PRODUCT_DECISIONS.md)。

## 参考项目怎样实现

分析对象为 [sdnwls/nai-style-lab](https://github.com/sdnwls/nai-style-lab)，本次读取的提交是 [`2fa20e2`](https://github.com/sdnwls/nai-style-lab/tree/2fa20e2e2b7fc1416642a1154ef26c46479630a2)。它使用 Python 引擎与 pywebview/WebView2，前端经桥接调用引擎，状态保存为本地 JSON，原图单独保存。

它的「Roll」包含整个偏好搜索循环：

1. **组串。** `Engine.start_random` 在配置范围内抽取不重复画师，为每位分配一位小数权重，拼成 NovelAI 的 `权重::artist:名称 ::`。`_draw_and_render` 对已出现过的字符串做有界重抽，逐张请求图片，逐张保存。公共提示词、角色、负面与 Seed 共用，使画风成为主要变化项。[生成实现](https://github.com/sdnwls/nai-style-lab/blob/2fa20e2e2b7fc1416642a1154ef26c46479630a2/app/engine.py#L395)
2. **定位与排名。** 新候选先沿已有排名二分定位，矛盾选择以最少违背投票的位置处理，定位期间不扰动已有候选分数。常规对决使用 Elo：期望胜率为 `1 / (1 + 10^((Rb − Ra) / 4000))`，初始 10000，K 为 320。这是常见 Elo 的十倍计分单位，并非图像质量的客观分数。[评分及定位](https://github.com/sdnwls/nai-style-lab/blob/2fa20e2e2b7fc1416642a1154ef26c46479630a2/app/core.py#L312)
3. **进化。** 上位约 30% 候选参与繁殖，变异、双亲交叉、全新随机各占约三分之一。变异会换、删、加画师并扰动权重；交叉混合父代画师。选择还参考父代排名、画师在优胜组合中的出现频率和估计贡献，避免单一画师占满所有后代。新一代与优胜组比较，通过后替换同等数量的低位候选，原条目转入排除状态。[繁殖实现](https://github.com/sdnwls/nai-style-lab/blob/2fa20e2e2b7fc1416642a1154ef26c46479630a2/app/core.py#L444)
4. **精修与复测。** 精修固定画师，只改变权重，扰动幅度从 ±0.3 缩到 ±0.2、±0.1，变体挑战当前冠军。最后再用多个 Seed 比较原串与冠军，减少只适合一个 Seed 的偶然结果。[精修流程](https://github.com/sdnwls/nai-style-lab/blob/2fa20e2e2b7fc1416642a1154ef26c46479630a2/app/engine.py#L1201)
5. **画师贡献估计。** `artist_scores` 用带正则化的线性拟合，将组合相对分数拆成各画师权重的贡献；低样本贡献会向零收缩。它是已选样本中的偏好估计，不能解释为某画师独立带来的因果质量。[贡献估计](https://github.com/sdnwls/nai-style-lab/blob/2fa20e2e2b7fc1416642a1154ef26c46479630a2/app/core.py#L851)

本项目独立实现上述创作思路，没有复制上游 Python、网页代码、原图或画师数据集；本次读取的仓库根目录没有 LICENSE 文件。

## NAI Atelier 的适配

| 环节 | 本项目行为 |
| --- | --- |
| 默认出图 | 首次只设每串画师数与本轮张数；点击开始后冻结配方，一次提交有限任务、逐张生成并保存，付费先确认整轮总费用。出图后留在画风库，不跳转两图比较或要求完成评价 |
| 画师来源 | 直接读取现有画师库的完整 Tag 词库，无需另建名单或预先收藏；样张继续由画师库管理，抽取不要求有图。搜索／手填只用于可选的锁定、排除或补充 |
| 创作控制 | 设置画师数与权重范围；锁定必选画师及其权重，排除暂不使用的画师；按规范化画师名和权重集合过滤重复组合 |
| 公平对照 | 每个实验保存完整提示词、角色、模型、尺寸、参数和固定 Seed。出现候选后公共配置冻结；改条件另建实验 |
| 保留偏好 | 卡片直接保存完整风格串，关联成功的 `savedChainId` 作为当前记录的偏好信号；没有保留项时全随机，有时每四套三套围绕保留组合探索、一套全新随机。继承约三分之二可用非锁定画师并小幅调权重，从完整词库补齐；不使用归档／验证副本、已排除或移出词库的画师，仍满足人数、锁定、权重和去重约束 |
| 可选排名 | 「可选工具 → 画风对比」只比较已有图片并记录偏好，不触发生图，主动进入盲选；旧排位仍沿固定对手二分定位，普通对决使用初始 1000、K=32 的可重放 Elo。画风库默认按最新生成，主动选Elo排序时才显示相对等级和分数 |
| 盲选 | 默认遮去画师和评分，左右同时就绪后才能选择；支持平局、跳过、撤销、同步放大和同位置观察 |
| 可选进化 | 从高位约 30% 取父代产生变异、交叉及随机组合，与本轮固定优胜组比较。明确完成本代时归档未胜出后代及可替换的旧低位；直接再Roll只结束旧轮次，不自动归档或删图 |
| 权重测试 | 详情「更多操作 → 权重测试」固定画师集合和锁定项，自动调整权重并生成有限测试图，再由用户选择；变体依次比较当前最佳方案，胜者继续迎战，平局保留冠军。继续测试时，调整幅度从 ±0.3 缩小到 ±0.2、±0.1；权重测试／验证未完成也可返回画风库或直接再Roll |
| 验证 | 原版与权重测试选出的方案在三个不同新 Seed 下生成六张图，只安排同 Seed 的三场比较；原版仍为冠军时只出三张，不重复同配方。验证副本与旧记录同存，但不混进常规画风库和排名 |
| 界面衔接 | 沿用工坊工具栏、卡片、图片偏好与原位多选；搜索与筛选靠近图库，人数／张数及参数在Roll旁下拉，记录管理在记录选择旁。自动布局最多四列并按容器宽度缩减，明确列数遵循全局设置；桌面详情侧栏，手机覆盖层 |
| 结果管理 | 按画师Tag、编号、状态和轮次查看，全部如实包含待生成；单项及批量保存、丢弃和恢复，记录重命名及可恢复收起。补齐仅提交当前未完成轮次可生成项，旧轮由用户选中后生成；批量保存逐项落盘、失败可续做 |
| 资产闭环 | 图片进入原有历史；爱心、图片复制和下载复用收藏及分享清洗。满意候选可保存为完整风格串，或送往实验室继续编辑 |

参考项目以对决排位为主，工坊按用户确认的省力目标改为「自动试一批，只保存喜欢的」；两图比较／权重微调保留为可选工具，不作为主线门槛。保存信号只指导后续配方抽取，不冒充自动审美，也不引入评图模型或额外调用。没有接入画师贡献回归、另建生图 Key／计费公式／任务引擎，不复制上游代码、图片或画师数据。

## 数据与恢复

- 实验资料通过 `/api/style-roll` 保存到既有私人 `settings`，按用户及实验 ID 隔离；没有新增数据库表、迁移文件或更改存储定位键。原有工坊备份覆盖这些设置与原图。
- 画师目录沿用画师库的完整分片读取与缓存，不受界面已加载页数或手填条目的 1000 项上限影响；实验只保存锁定／排除等覆盖项与实际候选，不把整份词库重复写进每个实验。目录读取失败会明确提示并允许重试，旧候选仍可查看、精确调权重或生成原配方。
- 候选与整条记录均使用可恢复状态收起，整条记录的可选 `archived` 字段兼容旧资料；不物理删除设置、历史或风格串。
- 保存携带版本号，后端比较旧值后写入；迟到页面不能覆盖另一端的新记录。冲突时保留当前页面并提示重新加载。坏存档明确报错，不用空实验覆盖。
- 生成使用既有 `buildGenerationJobDescriptor` 与 `beginGenerationSeries`。后台任务新增有限 `sequence`，逐项保留各候选的提示词、Seed 和历史来源；起跑前校验整列，拒绝嵌套与数量不符，沿用同 Key 的整轮互斥、间隔、后台保存与费用上涨确认。用户取消或失败不会重新抽串、自动续跑；明确继续仅提交本轮未生成且未评价的原配方。上游 502 等错误网页不会原样进入横幅或排队弹窗，改为简短状态说明；生成错误可关闭，使用「补齐剩余」主动重试缺图，保留已出图片、原配方与对比记录。「重新加载」只用于资料读取等请求错误。
- 历史通过实验来源 ID 与候选模块 ID 关联，按轻量索引分页恢复。切页不取消已提交任务，关闭／刷新行为遵循已有任务服务，不新建重启自动续跑任务。
- 对比除了实验快照，还核对实际历史中的全部参数与负面词；官方参数规范化导致条件变化时不会混比。每张投票记录两张实际历史 ID，已评图消失时保留分数和缺图状态，不拿后来图片替代。
- 默认批次使用新增可选轮次类型 `batch`，出图即可完成，无对手与必做投票；旧随机／进化／权重微调轮次仍可读取。下一轮可关闭未完成的旧轮次，不改写原配方、原图、投票或执行归档；已经关闭的轮次不能重开。投票账本与普通两图比较评分仍保留。
- 固定 Seed 不被实验室的「强制置空」偏好随机化。历史读取失败不被视为「尚未生成」，任务回执中的已保存图片先保留，避免因列表回读失败重复消费；后台暂停、费用补充授权和取消均由用户主动操作，切 Key 不授权旧任务。
- 「存为风格串」保存实际生成参数，并通过既有上传入口持久保存独立封面；后续编辑不反写实验。导出的 JSON 是实验配置与投票记录，不含图片、Key 或账户设置，不能代替完整工坊备份。

## 维护入口

- `services/styleRoll.ts`：数据约束、组串、谱系、评分与配对纯逻辑。
- `services/styleRollWorkflow.ts`：有限轮次、二分排位、进化确认、冠军挑战与同 Seed 验证。
- `services/styleRollApi.ts`、`styleRollGeneration.ts`：既有存储、历史及后台生成的接缝。
- `services/styleRollWorkspace.ts`：图库范围、搜索排序与补图资格，展示和提交共用。
- `components/StyleRollPage.tsx`、`components/roll/`：工坊图库、记录管理、原位多选、配置与可选盲选界面。
- `worker/generationJobs.mjs`、`mobile/generationJobModel.ts`：共用有限多配方任务及手机解析，保留既有费用和后台执行语义。
- `worker/routes/styleRollRoutes.ts`：私人资料验证与并发版本检查。
- `tests/services/styleRoll*.test.ts`、`tests/components/StyleRoll*.test.tsx`、`tests/worker/styleRollRoutes.test.ts`：合成资料回归；App 导航、助手页面和五语测试另有对应集成覆盖。

实际 NovelAI 生图需要创作者在界面主动发起；工程测试不消费真实额度，不读取私人资料作为夹具。
