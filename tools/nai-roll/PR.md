# feat(nai): 一键 Roll 与 Roll 内容搭配库（纯内容快照），并修复选择面板与发布链路

## 概述

在 `一键 Roll` 工作区里补齐一套完整的内容组合流程，并新增独立的 **Roll 内容搭配库**：只保存六类内容（人物形象 / 服饰穿搭 / 动作互动 / 表情状态 / 场景环境 / 镜头画面）及它们自身的约束，**不保存画师串、风格负面与生图参数**，因此同一套内容可以配任意画风，同一画风也能配不同内容。

同时修掉三个实际使用问题：文生图里选词库的面板把候选列表挤成一条缝（点不到条目）、图片提示词库要先进只读预览才能编辑、Roll 内容库的封面只能上传本地文件。

> 本仓库是完整源码仓库，而这批改动是在**已构建产物**上通过补丁脚本实现的（`dist/assets/*` 为 Vite 产物）。
> 因此本 PR 交付的是**可复现的补丁 + 片段 + 验收套件 + 说明**，不替换 `dist`、不动源码，避免出现「仓库 dist 与源码不一致」的混装状态。

## 一、一键 Roll

- 六库各抽 1 条；池按 `type` 取、按 id 排序，与接口返回顺序无关。
- **每栏独立随机流**（`seed#kind`）：固定/取消某栏不影响其它栏抽到什么。
- 参与 / 固定：取消参与的栏置灰并写明「本次不参与：不抽取、也不会填入实验室」；空库不允许固定；固定项若已失效会标注并如实重抽。
- 单栏「换一个」：只动该栏，池 > 1 时**排除当前条目**（确定性换掉，不靠重试）；池 = 1 显示「仅 1 条」；空库转「去添加」。
- 全局「再抽未固定项」：只换未固定的，候选不足时**保留并如实说明**（不做无限重试）。
- 会话内最多 20 组历史，上一组 / 下一组；**还原这组**（用记录快照）与**按当前词库重算**（同随机码重算）是两个分开的动作。
- 证据含算法版本、组合随机码、每栏随机流、参与与固定状态、每栏条目 id、候选池指纹；**组合随机码不是生图 seed**，界面上写明。

## 二、填入实验室：先确认、再整表写入、可一次撤销

- 先弹确认面板：**目标角色**（真实角色名 + 稳定 id；没有可靠上下文时不预选第一个角色；没有角色时默认新建；取消不创建）、逐栏「当前 → 将填入」、动作（改为保留 / 改为填入）、来源状态（仍有效 / 已更新 / 已不存在）、**负面与约束**、未覆盖检查说明。
- 六类内容按 **picker 同一形状**的 `meta` 写入（来源快照、中英对照、标签、预览图、应用时间、是否需要复核），条目自身的负面进**该分类的负面槽位**，四态派生的约束进备注；四态原文副本保留，**不猜测、不回写词库**。
- 写入是**一次状态变更**（含主体提示词同步），避免「栏位换了、旧文还留在主体里」的半套状态；应用后常驻「撤销本次 Roll 填入」，**一次撤销覆盖本次全部范围**；若会覆盖应用后的手改，先说明影响并要求确认。
- 存为搭配沿用既有 `type='preset'` 落点，但用**稳定操作 id**（`agent-<64hex>`）重试同一个 POST（服务端幂等回放）、显示**服务端回执 id**、四态（保存中 / 已保存 / 明确失败 / 结果待确认），断网可「核实保存结果」，**不再用 PUT 覆盖**。

## 三、Roll 内容搭配库（纯内容快照）

- 独立入口「Roll 内容库」：卡片列表、搜索（名称 / 标签 / 备注）、排序、只读预览、显式改名、复制、删除、载入实验室、**从完整搭配人工提取**。
- 保存用**白名单构造**（不是复制整份 `params` 再删字段）：只取六类内容 + 内容负面 / 缺席约束 / 备注 / 来源快照 + 记录名 / 备注 / 标签 + 结构版本 + Roll 证据；落点是 `chains` 表 `params` 下的独立字段，与旧「完整搭配」的快照字段**物理分开**，既有「载入搭配」列表已过滤纯内容记录，旧记录语义不变。
- 载入与「一键 Roll 填入」**共用同一套确认面板与引擎**，但**只用记录里的快照**（来源条目改名 / 改内容 / 删除都不改变已存内容），并且计划里**没有风格块、没有随机码**——画师风格、风格配套负面、用户手填全局负面、模型与全部生图参数都不在计划里；内容负面按分类落到对应角色的槽位，不上提到全局。
- 封面**从本地生图历史里选**：分页缩略图网格（`/api/media?…&variant=thumb-320`）、收藏星标、加载更多；选中后服务端把历史图复制一份进封面桶（与「服饰 / 角色封面从历史选图」同一条既有路径），原历史图被清理也不影响封面；另保留「上传本地图片」兜底与「清除封面」。

| 文生图里选词库的面板：候选条目点不到、看清不了 | 面板底部固定说明用 `max-height:64%` 吃掉 60% 高度，把列表挤到 82px；命中测试显示点击命中的是底部而不是条目。改为底部限高 + 说明区自滚 + 操作区不压缩 + 列表保底 + 面板高度上限调整并按视口夹取 |

## 五、发布链路（这次白屏的根因）

构建产物里同一个入口出现过两种查询串（`index.html` 用 `…?atelier-v170-76-ui1-roll1-entry1-expand1`，`ChainEditor` 用 `…?atelier-v170-76`），浏览器把它们当**两个模块**，于是 `index`（含 React）被加载两份，打开实验室即 `React error #321（Invalid hook call）`。

- 新增**版本查询串归一**脚本：把历史上叠加的后缀统一收成 `atelier-v<ver>`，并在结尾**自检「整个 dist 只能有一种版本串」**（不符合则退出码非 0）。
- 新增**一条命令的发布脚本**：打补丁 → bump → 归一 → 四个产物 `node --check`；补丁脚本本身也从「见到标记就跳过」改成**每次从干净产物重建**再注入（否则改了片段但产物不更新）。

## 使用约束

- 不调用生成接口、不消耗任何额度；不新增表 / 接口 / schema；抽中的条目**只读**，不改写词库条目。
- 生产侧全程只读（只做 GET 与实验室只读「查看实际请求」）。
- 载入内容不会覆盖画师风格、风格配套负面与全部生图参数；内容负面只进对应分类的槽位。
- 安全模式下，落在图片上的第一次点击会被应用的「显示图片」处理器接管，因此选封面需要点两下（与应用内其它图片一致）。

## 基线

基于 `origin/main`（`e7f1e3c feat: add default-enabled unrestricted mode for creative assistant`）。

补丁默认写入已安装的运行时目录，可用环境变量 `NAI_RUNTIME` 指向别处；验收套件默认跑在隔离实例 `http://127.0.0.1:3055`（`testenv/start.mjs` 启动，独立 `persist` 目录），不会碰 `:3000` 上的生产实例。
